Every robot in this guide is controlled by a computer called the V5 Brain. It doesn't look much like a laptop, but it works the same way. And the way computers work is surprisingly simple: nearly everything comes down to storing numbers and doing basic math on them, very quickly.

You can write working code without knowing any of this. But the moment something strange happens, like a number that overflows, a program that runs too slowly, or a pointer that crashes your robot, the explanation is on this page. It's also where this guide starts using real technical vocabulary. Words in bold are terms programmers actually use, and they'll keep coming up. Every one of them is collected in the [Glossary](../../reference/glossary/).

## Everything is a number

A computer's memory is built from billions of tiny electrical switches, and each one is either off or on. We write those two states as 0 and 1. One switch holds one <Term id="bit">bit</Term>, the smallest possible piece of information.

One bit can't say much, so computers group them. In everyday numbers, each place is worth ten times the place to its right: ones, tens, hundreds. Group bits together and each place is worth *two* times the place to its right: ones, twos, fours, eights. That system is called <Term id="binary">binary</Term>, and it can write any whole number using only 0s and 1s.

A group of 8 bits is called a <Term id="byte">byte</Term>. It's the basic unit of memory, and everything you've ever heard measured in megabytes or gigabytes is counted in these. Drag the slider to see how a byte holds a number.

With every bit on, a byte holds 255, so it can represent 256 different values, counting zero. Need bigger numbers? Use more bytes. Two bytes reach 65,535, and four bytes reach over 4 billion.

Long strings of 0s and 1s are hard for people to read, so programmers often use <Term id="hexadecimal">hexadecimal</Term>, or hex, which counts in sixteens using the digits 0 to 9 and then A to F. One hex digit stands for exactly 4 bits, so any byte fits in two hex digits. Hex numbers are usually written with `0x` in front, as in `0xFF` for 255. You'll run into them all over the place, including colors and memory addresses.

It isn't only math that's stored this way. Text is numbers, where each letter has an agreed-upon code. Images are numbers giving each pixel's color. A program itself is numbers too, which turns out to be the key idea of this page.

## Memory is a row of numbered bytes

Picture a very long row of boxes, each holding one byte. This is <Term id="ram">RAM</Term> (random access memory), the computer's working memory. Each box has its own permanent number, called its <Term id="address">address</Term>, and addresses are how a computer refers to any piece of data: "the byte at address 2". *Random access* means that it takes the same time to reach any address, in any order.

Two facts about these boxes matter for everything that follows:

- A byte always holds *something*. You can't empty it, only replace what's in it.
- Reading a byte doesn't change it. Writing to a byte destroys what was there before.

RAM is also <Term id="volatile-memory">volatile memory</Term>, which means it forgets everything when the power goes off. A running program keeps its data here, and that's why turning your robot off and on again resets everything it had worked out.

Larger values take up several bytes in a row. The V5 Brain's processor is a 32-bit design, so it naturally handles 32 bits, or 4 bytes, at a time. That size is its <Term id="word">word</Term>. A 4-byte number at address 100 occupies addresses 100, 101, 102 and 103.

## The CPU does the work

The <Term id="cpu">CPU</Term> (central processing unit) is the part that actually does things, and its abilities are limited. It can't think, and it has no idea what a robot is. It holds a few values at a time in <Term id="register">registers</Term>, small storage slots built directly into it, which are by far the fastest memory in the computer. A math circuit called the <Term id="alu">ALU</Term> (arithmetic logic unit) does calculations and comparisons on those registers.

Everything a CPU can do comes as an <Term id="instruction">instruction</Term>: one small command, like "copy this byte into a register", "add these two registers", or "if this register is zero, go to a different instruction". The full list a given CPU understands is its <Term id="instruction-set">instruction set</Term>.

Here's the key idea: instructions are stored in memory as numbers, right next to your data. A program in this form is called <Term id="machine-code">machine code</Term>. To keep its place, the CPU has a special register called the <Term id="program-counter">program counter</Term>, which holds the address of the next instruction. Then it repeats three steps, over and over, for as long as it has power. This loop is the <Term id="fetch-decode-execute">fetch-decode-execute cycle</Term>.

Adding two numbers took four instructions. Most of the work was moving data around, and that's normal. Real programs spend a large share of their time doing just that.

The instructions in the animation are written in a readable form called assembly language. You won't write it in this guide, but the next page shows how the code you do write gets turned into it.

### How fast is it?

A CPU runs on a clock: an electronic signal that ticks at a steady rate, and every step of its work happens on those ticks. Ticks per second is its <Term id="clock-speed">clock speed</Term>, measured in hertz. One megahertz (MHz) means a million ticks per second. The V5 Brain's processor runs at 667 MHz, and VEX rates it at 1,333 million instructions per second. Think about that next to the four-instruction program you just watched.

## Why there are different kinds of memory

If registers are so fast, why not make all memory out of them? They're expensive, power-hungry, and physically large for what they hold, so a CPU only has a few. Computers instead stack several kinds of memory, trading size for speed.

To avoid waiting on RAM, a CPU keeps recently used data in a <Term id="cache">cache</Term>, a small, very fast memory built into the chip. Programs can't see it directly, but it's why reading through an array in order is much faster than jumping around.

Programs need to survive being powered off, so they're kept in <Term id="non-volatile-memory">non-volatile memory</Term>. On the Brain, that's <Term id="flash-memory">flash memory</Term>, where your uploaded programs live, and optionally an SD card. It's the same idea as a phone's storage, and it's much slower than RAM.

## The V5 Brain

You can now read a computer's spec sheet. Here's the Brain's:

| Part | V5 Brain | What it means for you |
|---|---|---|
| User processor | ARM Cortex-A9, 32-bit, 1,333 MIPS | Runs your program. A second, separate processor runs VEXos, the Brain's operating system. |
| RAM | 128 MB | Room for your program's data, and more than most robot programs will ever use. |
| Flash | 32 MB | Stores uploaded programs, in up to 8 program slots. |
| Expansion | Up to 16 GB SD card | Lets you save logs and data, covered in [Logging to the SD Card](../../seeing-inside/sd-card-logging/). |

## What to take with you

When you write code, you're telling the CPU which memory to read, what to do with it, and where to put the result. [The next page](../what-code-does/) shows what that looks like, and how the code you write becomes the machine code you just watched.

<Check prompt="A program writes the number 40 to a byte that holds 7, then reads that byte twice. What does each read give, and what's in the byte afterward?">
Both reads give 40, and the byte still holds 40. Writing replaced the 7 for good, and reading never changes memory.
</Check>

<Check prompt="A sensor gives you a value from 0 to 1000. Is one byte enough to store it? What's the smallest number of whole bytes that works?">
No. One byte tops out at 255. Two bytes hold up to 65,535, so two is enough.
</Check>

<Check prompt="What's the value of the byte 00001010 in binary? And what does the program counter hold right after the CPU fetches the instruction at address 500, if each instruction takes one address?">
The 8 and 2 places are on, so 8 + 2 = 10. The program counter holds 501, because it moves on during the fetch. (On real processors, instructions usually take 4 bytes, so it would move by 4.)
</Check>
